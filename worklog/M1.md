# M1 工作日志

本文件只由 M1 追加，其他成员不要编辑。新条目追加在文件末尾。

条目格式（照抄下面这一段，逐行填写，目标是 1 分钟内写完）：

```
## T-0xx · M1 · YYYY-MM-DD
- 内容:
- 产出:
- 提交:
- 用时:
- AI:  · 校验:
- 状态:
- 备注:
```

字段说明：

- `内容` 实际做了什么。
- `产出` 实际改动/新增的路径，多个用 ` · ` 分隔。
- `提交` commit 短哈希；如果走了 PR，追加 ` · PR #n`。
- `用时` 近似有效工时，按 0.5 h 取整，自报即可。
  工时、提交数、代码行数、提示词条数、token 用量都**不是**贡献度分数，
  不会被单独拿来衡量任何人。贡献度由任务范围、产出、校验方式、提交、
  评审与集成工作、以及日志共同还原。
- `AI` 用了哪个工具；没用就写"无"。`校验` 是**必填**：说明你如何确认
  产出是对的。任务的人类负责人始终是作者，并对结果负责。
- `状态` todo / wip / review / done / blocked / dropped。
- `备注` 阻塞、遗留问题、移交说明。

## T-005 · M1 · 2026-09-23
- 内容: Problem-F 接入守卫与公开安全门修复，并先行登记 T-005..T-012 任务图。
  两个缺陷：(1) 主办方 Problem-F 素材在工作区里是 untracked 但**未被忽略**，
  一次 `git add -A` 会暂存 2,014 个文件约 552 MB，其中含带注入文本层的 PDF 与
  本地审计证据；(2) 安全门把 Git 对非 ASCII 路径的引号转义形式直接交给
  `Test-Path -LiteralPath`，路径里的引号是非法字符，报的是非终止错误，于是该
  文件被**跳过**——体积与凭据检查从未运行，门却报告成功。超过 10 MB 失败线的
  三个文件正是这样被放过的。修复采用双重防御：`core.quotePath=false` 加把控制台
  编码钉到 UTF-8；若钉不住则退回 Git 默认引号形式（纯 ASCII，与编码无关）再显式
  解码；两种模式都可能有残留引号，故无条件解码。无法解释的路径现在是**失败而非
  跳过**，并新增 `quoted paths: N decoded, M uninterpretable` 计数器。
- 产出: TASKS.md · .gitignore · scripts/check_public_safe.ps1 ·
  scripts/selftest_checker.ps1 · README.md
